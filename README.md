# vk2tg: пересылка сообщений ВКонтакте → Telegram-канал

Внутренний сервис (VKover лицензирован под AGPL-3.0, сервис не распространяется).
Получает новые сообщения из выбранных бесед ВК от имени пользовательского аккаунта,
дедуплицирует и публикует их в один Telegram-канал через бота.

## Проверено (раздел 11 ТЗ, исходники `vkover==0.2.10`)

| № | Что проверялось | Результат |
|---|---|---|
| 1 | Диспетчер вызывает синхронные обработчики | ✅ `Dispatcher.dispatch` вызывает `fn(ev)` без `await`. `async def`-обработчик из README VKover не заработал бы. Исключение в обработчике выходит из `vk.run()`, поэтому обработчик обёрнут в `try/except`. |
| 2 | `vk.history` возвращает поля сообщения | ◑ По коду: `messages.getHistory(extended=0)` → `Message.from_api` берёт `attachments`, `fwd_messages`, `conversation_message_id`, `out`, `reply_message`; весь ответ в `Message.raw`. Порядок: новые первыми (`rev=0`). `fwd_messages` остаются сырыми словарями. Наличие ключа `action` у служебных сообщений по исходникам не проверить (ответ живого API): **проверить на реальном аккаунте**. |
| 3 | Структура `photo` | ◑ Код библиотеки вложения не разбирает. Реализация использует `photo.sizes[].url/width/height` и устойчива к отсутствию полей. **Проверить на реальном аккаунте.** |
| 4 | Ответ `groups.getById` | ◑ По исходникам не проверить. Поддержаны обе формы: список и `{"groups": [...]}`; при ошибке автор — `id{from_id}`. **Проверить на реальном аккаунте.** |
| 5 | Исключения при недействительной сессии | ✅ `TokenExpired(VKError)` бросает `Client.call` при кодах 5/1110, если обновление токена не помогло; `vk.run()` пробрасывает его из `LongPoll.connect`. Прочие ошибки API — `VKError`; сетевые сбои `client.call` — `httpx.HTTPError`. `vk.run()` при `VKError`/сетевой ошибке на первом подключении завершается целиком, поэтому поток VK запускается в цикле с повтором. |
| 6 | Доступность `vk.client.call` для замка | ✅ `LongPoll` и `VKover` используют один объект `Client`; подмена атрибута экземпляра действует везде. Long poll идёт через отдельный httpx-клиент и замок не блокирует. |

### Расхождения с ТЗ и решения владельца

- **FR-7:** в ТЗ `vk.me()["id"]`, в VKover `me` — свойство. Используется `vk.me["id"]` (решение владельца).
- **FR-2 (дополнение):** обновление токена внутри `vk.run()` (`refresher.refresh`) запускает Chromium мимо `client.call`. Тем же замком обёрнут и `refresher.refresh`, чтобы два Chromium не открывали один профиль (решение владельца).

### Мелкие отклонения/уточнения

- Добавлены `requirements.txt` и `requirements-dev.txt`, `pytest.ini`, `tests/conftest.py` (в структуре ТЗ не перечислены).
- Повторы (`with_retries`) живут в `telegram_sink.py` и используются также для скачивания фото.
- Если `web_token.json` отсутствует или повреждён при старте, это обрабатывается как недействительная сессия (уведомление владельцу, код 0), иначе ручная проверка 4 не работала бы после удаления файлов.
- Сигналы long poll, накопленные за время одного опроса, сводятся к одному `fetch_all`. Первый полный опрос выполняется сразу при старте (забирает пропущенное за время простоя, FR-5).
- Docker-образ и compose в этой среде **не собирались** (нет Docker): проверен только синтаксис compose-файла.

## Первый вход

```bash
cp .env.example .env && cp config.example.yaml config.yaml   # заполнить
mkdir -p data
docker compose build
docker compose --profile login run --rm --service-ports login
```

С локальной машины:

```bash
ssh -L 5900:127.0.0.1:5900 user@server
```

Подключитесь VNC-клиентом к `localhost:5900`, войдите в отдельный аккаунт ВК.
Когда токен сохранится в `data/web_token.json`, команда завершится.
Вход выполняется один раз на том сервере, где работает приложение.

## Запуск и логи

```bash
docker compose up -d            # app + redis
docker compose logs -f app      # логи
docker compose stop app         # остановка
```

Формат строки лога: `время УРОВЕНЬ [чат] cmid=N результат` — «отправлено», «дубль (а)»,
«дубль (б) of …», «пропущено: …». Ошибки — уровень ERROR со стеком.

При недействительной сессии владелец получает сообщение в Telegram, контейнер
останавливается (код 0, `restart: on-failure` не перезапускает). Повторите вход и
запустите `docker compose up -d`.

Telegram-бот должен быть администратором канала с правом публикации.
